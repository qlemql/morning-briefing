# Morning Briefing — 아침 브리핑

[English](README.md) · **한국어**

> 임원층을 위한 매일 AI 한국어 브리핑 앱. 사용자가 늘어도 API 비용이 일정하게 유지되도록 공유 캐시 아키텍처로 설계했고, 혼자 운영해도 단일 장애점이 되지 않도록 다층 안정성 장치를 얹었습니다.

📱 App Store에서 다운로드

## 왜 만들었나요?

매일 출퇴근에 왕복 두 시간 이상을 씁니다. 그 시간에 뉴스 피드를 스크롤하는 대신, 정말 중요한 것만 5분 안에 읽을 수 있는 무언가가 필요했습니다 — 일에 도움이 되는 경제·투자 맥락 같은 것들요.

어려운 건 UI가 아니라 비용 구조였습니다. LLM 기반 소비자 앱은 대부분 사용자별로 콘텐츠를 생성합니다. 그러면 API 지출이 사용자 수에 비례해서 늘어나죠. 혼자 운영하는 사이드 프로젝트에서는 사용자 50명쯤에서 수학이 깨집니다. UI를 짜기 전에 다른 아키텍처가 필요했습니다.

## 어떻게 동작하나요

**공유 일일 캐시.** 모든 사용자가 같은 날 같은 브리핑을 봅니다. 콘텐츠는 카테고리별로 하루에 한 번만 생성되어 서버의 Upstash Redis에 캐싱되고, 클라이언트의 `localStorage`에서 읽힙니다.

```
클라이언트 → localStorage("briefing_economy_2026-06-10") 확인
          → 캐시 미스 → POST /api/briefing
          → 캐시 히트 → 렌더링

서버      → 오늘 이미 생성됐나? (Redis)
          → 예  → 캐시된 내용 제공
          → 아니오 → Claude 호출 → 저장 → 제공
```

결과: **사용자 수와 무관하게 API 비용이 하루 단위로 거의 고정됩니다.** 1000번째 사용자가 첫 번째 사용자와 같은 비용이고, 하루·한 달 예산 가드가 지출을 하드캡으로 막아 폭주 호출이 비용을 덮치지 못하게 합니다.

**하나에 집중, 여럿을 염두에 둔 설계.** 지금은 데일리 신선도가 비용값을 하는 카테고리 하나 — 경제/시사 — 만 운영합니다. 카테고리 시스템은 설정 기반(`enabled` 플래그)이라, 투자·생활/테크는 한 줄이면 다시 켤 수 있습니다.

**전면 무료, 후원 모델.** 모든 카드가 무료입니다. 처음엔 2·3번 카드 페이월이었지만, 후원 모델로 전환했습니다 — 매일 진짜 쓸모 있는 한 편을 무료로, 마음이 동하면 "커피 한 잔" 후원으로.

**지난 브리핑 다시 보기.** 생성된 모든 날을 365일간 보관합니다. 날짜 스테퍼, 좌우 스와이프, `?date=` 딥링크로 지난 아침들을 거슬러 볼 수 있어요 — 과거 날짜는 archive에서 바로 불러오고 재생성하지 않아, 과거를 둘러봐도 비용이 0입니다.

**돌봄 없이도 굴러가는 안정성.** 매일 생성은 Vercel cron으로 돌고, 2차 "워치독" cron과 호스팅 플랫폼에 독립적으로 동작하는 외부 GitHub Action이 이를 한 번 더 트리거·검증합니다 — 아침이 비면 Telegram으로 알려주는 데드맨 스위치죠. 생성이 실패해도 evergreen 폴백이 앱을 계속 서빙합니다.

**iOS는 Capacitor로.** 같은 Next.js 코드베이스가 Capacitor 8을 통해 네이티브 iOS 앱이 됩니다 — 오프라인 지원, 푸시 알림, 로컬 알림, 배지 카운트까지 플러그인으로 처리합니다.

## 주요 기능

- 공유 일일 캐시(Upstash Redis) + 날짜 키 무효화 — 고정 API 비용
- 하루·한 달 예산 가드와 evergreen 폴백
- 지난 브리핑 아카이브(365일) — 날짜 스테퍼·스와이프·공유용 `?date=` 링크
- 다층 안정성: Vercel cron + 워치독 cron + 외부 GitHub Action 하트비트 + Telegram 알림
- 서버 측 API 키 처리 — 클라이언트에 절대 노출되지 않음
- Capacitor를 통한 iOS 네이티브 배포, 오프라인 모드와 푸시 알림 지원
- 관리자 대시보드: 예산·분석·시스템 상태·수동 재생성

## 배운 것

UI를 짜기 **전에** 캐시 레이어를 설계한 것이 이 프로젝트에서 가장 중요한 결정이었습니다. 몇 시간 만에 동작하는 UI와 첫날부터 지속 가능한 비용 구조를 동시에 가졌습니다. 사용자별 생성을 먼저 출시하고 나중에 캐시를 끼워 넣으려 했다면, 데이터 모델이 매 단계에서 저를 가로막았을 겁니다.

두 번째 교훈은 어렵게 얻었습니다: **조용히 실패하는 예약 작업은 아예 없는 것보다 나쁩니다.** 매일 생성이 며칠 아침을 소리 없이 건너뛰었고, 유저는 오래된 폴백 콘텐츠를 보는데 저는 우연히 들여다보기 전까지 몰랐습니다. 해법은 더 큰 재시도가 아니라 "이게 깨지면 내가 어떻게 알지?"를 설계하는 것이었어요 — 인앱 워치독, 방금 실패한 그 플랫폼에 기대지 않는 외부 하트비트, 그리고 제 폰까지 닿는 알림. 해피 패스는 쉬운 80%였습니다.

## 프로젝트 구조

```
src/
├── app/
│   ├── page.tsx                 홈 — 단일 카테고리 피드 + 날짜 내비게이션
│   ├── admin/page.tsx           운영 대시보드 (예산·상태·재생성)
│   ├── archive/                 지난 브리핑 (목록 + /archive/[date])
│   └── api/
│       ├── briefing/route.ts    오늘의 브리핑 (생성 또는 캐시 서빙)
│       ├── archive/route.ts     날짜별 지난 브리핑 (365일 보관)
│       └── cron/route.ts        매일 생성 (멱등·워치독 안전)
├── components/                  BriefingCard, CategoryTab, CardSkeleton, …
├── lib/
│   ├── claude.ts                Claude API 클라이언트 (웹검색 + 재시도)
│   ├── server-cache.ts          Redis 기반 일일 캐시 + 365일 아카이브
│   ├── budget.ts                하루·한 달 지출 가드
│   ├── alert.ts                 운영자 알림 (Telegram)
│   ├── kv.ts                    Upstash Redis 래퍼
│   └── cache.ts / types.ts      클라이언트 캐시 유틸 + 공유 타입
└── constants/index.ts           카테고리(enabled 플래그) + 설정

.github/workflows/daily-briefing.yml   외부 트리거 + 신선도 하트비트
vercel.json                            Cron 스케줄 (매일 + 워치독)
ios/                                   Capacitor iOS 프로젝트
```
