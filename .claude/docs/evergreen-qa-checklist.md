# Evergreen Content QA Checklist

> 용도: API/파이프라인 장애 시 대체 표시되는 에버그린 콘텐츠 검수 기준
> 담당: ContentQA
> 최종 수정: 2026-03-27

---

## 1. 팩트 정확성 (Fact Accuracy)

| # | 체크 항목 | 판정 기준 | FAIL 조건 |
|---|----------|----------|----------|
| 1-1 | 통계 수치에 원출처가 명시되어 있는가 | "한국은행 2025년 보고서" 등 기관명+연도 필수 | 출처 없는 수치 |
| 1-2 | 수치가 원출처와 일치하는가 | 출처 URL 또는 공신력 있는 2차 소스로 크로스체크 | 불일치 또는 검증 불가 |
| 1-3 | "약 N%", "N만명 이상" 등 근사 표현이 적절한가 | 정확한 수치 대신 근사치 사용 시 원본과 오차 5% 이내 | 오차 5% 초과 |
| 1-4 | AI 환각 의심 표현이 없는가 | 존재하지 않는 기관, 법률, 통계를 언급하지 않는지 확인 | 검증 불가능한 사실 주장 |

**검증 방법**: 카드당 핵심 수치 최소 1개를 원출처에서 직접 확인. URL이 있으면 WebFetch로 페이지 내용 대조.

---

## 2. 시의성 독립 (Time Independence)

| # | 체크 항목 | FAIL 표현 예시 | 허용 표현 예시 |
|---|----------|---------------|---------------|
| 2-1 | "올해", "금년", "이번 해" 사용 금지 | "올해 경제 성장률은..." | "2025년 경제 성장률은..." |
| 2-2 | "최근", "요즘", "근래" 사용 금지 | "최근 금리가 올랐습니다" | "2024~2025년 금리 인상 추세에서..." |
| 2-3 | "지난달", "이번 주", "어제" 사용 금지 | "지난달 발표된..." | "2025년 2월 발표된..." |
| 2-4 | "현재", "지금" 사용 금지 (서술적 맥락에서) | "현재 코스피는..." | 구조적/원리 설명은 "현재" 허용 (예: "현재가치 할인법") |
| 2-5 | 특정 시점에만 유효한 사실 금지 | "대통령이 발표한 정책..." (정권 교체 시 무효) | 제도/구조적 설명 위주 |
| 2-6 | 계절성 표현 주의 | "여름에 맞춰..." (겨울에 노출 시 부자연스러움) | 계절 무관한 주제이거나 "매년 여름" 등 반복 패턴으로 서술 |

**원칙**: 6개월 후, 1년 후에 읽어도 어색하지 않아야 한다.

## 3. 글자수 규격 (Length Specs)

| # | 항목 | 규격 | 측정 방법 |
|---|------|------|----------|
| 3-1 | 제목 | 20자 이내 | 공백 포함, 한글/영문/숫자 각 1자 |
| 3-2 | 요약 (인사이트) | 60자 이내 | 공백 포함 |
| 3-3 | 본문 | 4~6문장 | 마침표/물음표/느낌표 기준 문장 카운트 |
| 3-4 | 필수 필드 존재 | 제목, 요약, 본문, 카테고리 태그 | 빈 문자열이면 FAIL |

> 참고: 에버그린 카드는 일반 브리핑 카드와 규격이 다름.
> 일반 카드: 본문 150자, 인사이트 40자, SNS 30자.
> 에버그린 카드: 제목 20자, 요약 60자, 본문 4-6문장 (CTO 구현 스펙 기준).

## 4. 위험 표현 (Danger Expression Filter)

### 4-A. 투자 권유 표현

| 유형 | FAIL 예시 |
|------|----------|
| 직접 매수/매도 권유 | "삼성전자를 사야 합니다", "지금이 매수 타이밍" |
| 특정 종목 추천 | "이 종목은 반드시 포트폴리오에", "숨은 우량주" |
| 수익률 보장/암시 | "연 10% 수익 가능", "손해 볼 일이 없는" |
| 긴급성 조장 | "지금 안 사면 늦습니다", "마지막 기회" |

### 4-B. 확정적/단정적 표현

| 유형 | FAIL 예시 | 허용 대안 |
|------|----------|----------|
| 미래 확정 | "반드시 오를 것입니다" | "상승 가능성이 있습니다" |
| 절대적 판단 | "가장 안전한 투자처" | "상대적으로 변동성이 낮은 편입니다" |

### 4-C. 정치적 편향

| 유형 | FAIL 예시 |
|------|----------|
| 특정 정당/정치인 지지/비판 | "A 정부의 실패한 정책", "B 당이 옳다" |
| 이념적 단정 | "자본주의만이 답", "규제를 풀어야만" |

**허용**: 객관적 사실 전달 ("정부가 N 정책을 발표했다"), 양면 제시

### 처리 규칙
- 1차 발견: 해당 문장 지적 + 수정 지시 -> CTO에게 리턴
- 2차 동일 문장 재발견: 해당 문장 삭제 후 통과

## 5. 출처 URL 유효성 (URL Validation)

| # | 체크 항목 | 판정 기준 |
|---|----------|----------|
| 5-1 | URL 형식이 올바른가 | https:// 또는 http:// 로 시작 |
| 5-2 | HTTP 200 응답을 반환하는가 | WebFetch 또는 curl로 확인, 3xx 리다이렉트는 최종 목적지가 200이면 PASS |
| 5-3 | URL이 출처 내용과 관련 있는가 | 전혀 무관한 페이지로 연결되면 FAIL |
| 5-4 | URL 죽었을 때 처리 | 해당 카드에서 URL 필드 제거, 본문 내 출처 언급은 기관명만 남김 |

**에버그린 특이사항**: URL은 시간이 지나면 죽을 확률이 높다. 가능하면 기관 메인 페이지나 위키피디아 등 장수 URL을 권장. 뉴스 기사 URL은 비권장 (1-2년 내 삭제 가능성).

## 6. 카드 간 주제 중복 (Topic Overlap)

| # | 체크 항목 | 판정 기준 |
|---|----------|----------|
| 6-1 | 동일 주제 카드가 2개 이상인가 | 핵심 키워드 3개 이상 겹치면 중복 의심 |
| 6-2 | 유사 주제이나 관점이 다른가 | "복리의 힘" vs "72법칙" -> 관점 다르므로 PASS, 단 연속 노출 금지 태그 필요 |
| 6-3 | 카테고리 분포가 편중되지 않았는가 | 전체 풀에서 한 카테고리가 50% 초과하면 WARN |

**권장 카테고리 분포** (5~10개 풀 기준):
- 경제/금융 기초: 2~3개
- 자기계발/커리어: 1~2개
- 산업/기술 트렌드: 1~2개
- 생활 경제 팁: 1~2개
- 기타: 1개

---

## 7. 톤/말투 일관성 (Tone Consistency)

| # | 체크 항목 | 기준 |
|---|----------|------|
| 7-1 | 대화체 사용 | "~입니다", "~이에요" 체, 논문체("~이다", "~된다") 금지 |
| 7-2 | 자연스러운 한국어 | 번역투 금지 ("그것은 ~하는 것이다", "~에 의해") |
| 7-3 | 전문 용어 설명 | 첫 등장 시 괄호 안에 쉬운 설명 병기 (예: "PER(주가수익비율)") |
| 7-4 | 카드 간 톤 편차 | 한 카드만 유독 딱딱하거나 가벼우면 FAIL |
| 7-5 | 이모지 사용 금지 | 본문/제목에 이모지 포함 시 FAIL |
| 7-6 | 과도한 감탄/강조 금지 | "정말 놀라운!!", "완전 대박" 등 과잉 표현 FAIL |

## QA Report 출력 양식

에버그린 카드 검수 시 아래 양식으로 결과를 보고합니다.

```
## Evergreen Content QA Report
- Date: YYYY-MM-DD
- Total Cards: N
- Status: PASS / FAIL

### Per-Card Results
| Card # | Title | Fact | Time-Ind | Length | Danger | URL | Tone | Result |
|--------|-------|------|----------|--------|--------|-----|------|--------|
| 1      | ...   | OK   | OK       | OK     | OK     | OK  | OK   | PASS   |
| 2      | ...   | WARN | OK       | FAIL   | OK     | DEAD| OK   | FAIL   |

### Fail Details
- Card 2 Length: 본문 8문장 (규격: 4-6문장)
- Card 2 URL: https://example.com/old-article -> HTTP 404, URL 제거 필요

### Topic Overlap Check
- 중복 없음 / [중복 카드 쌍 목록]

### Category Distribution
- 경제/금융: N개, 자기계발: N개, ...

### Action Items
1. [CTO에게 전달할 수정 사항]
```

## 검수 프로세스 요약

```
CTO 에버그린 카드 제출
  -> ContentQA 7개 항목 전수검사
    -> PASS: Manager에게 보고, 배포 승인 요청
    -> FAIL: CTO에게 Fail Details + Action Items 리턴
      -> CTO 수정 후 재제출
        -> ContentQA 재검수 (FAIL 항목만)
```
